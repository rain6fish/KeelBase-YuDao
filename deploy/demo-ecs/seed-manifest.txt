# KeelBase-YuDao 部署种子清单 —— `bootstrap-db.sh` 的唯一来源。
#
# 每一份 `sql/keelbase-*.sql` 都必须在这里出现且只出现一次，三态之一：
#
#   load      由 `bootstrap-db.sh` 第 4 步按本文件顺序导入。**顺序就是依赖顺序**：父菜单先于子菜单，
#             目录的授予先于它下面的页。
#   separate  由自己的步骤跑 —— 它要参数（`origin`），或不能放进那个循环。
#   skip      本部署不需要。`#` 后必须写理由；没有理由的 skip 视为漏分类。
#
# 新增一份 `sql/keelbase-*.sql` 而不在这里归类 ⇒ `scripts/check-seed-list.mjs` 红。
# 清单里点名一份不存在的文件 ⇒ 同样红。检查也核对「给 keelbase-ui 页面插菜单行的文件」必须在
# `load` 里，以及 `load` 落下的顶级路径都在 `module-scope.sql` 的保留清单里。
#
# ---
#
# KeelBase-YuDao deployment seed manifest — the single source for `bootstrap-db.sh`.
#
# Every `sql/keelbase-*.sql` appears here exactly once, in one of three states:
#
#   load      applied by step 4 of `bootstrap-db.sh`, in this file's order. **The order is the
#             dependency order**: a parent menu before its children, a directory's grant before the
#             pages under it.
#   separate  run by its own step — it takes a parameter (`origin`), or cannot sit in that loop.
#   skip      not needed by this deployment. A reason is mandatory after `#`; a skip without one reads
#             as an unclassified file.
#
# A new `sql/keelbase-*.sql` that is not classified here ⇒ `scripts/check-seed-list.mjs` is red. A
# manifest entry naming a file that does not exist ⇒ red too. The check also holds that any file
# seeding a menu row for a keelbase-ui page is on `load`, and that the top-level paths `load` lays are
# on the keep list in `module-scope.sql`.
